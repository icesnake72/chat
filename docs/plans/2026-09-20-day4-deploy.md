# 4일차 배포 계획 — chat-app을 board 스택과 함께 Lightsail에 올리기

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `https://sbs.alldayai.org`에서 채팅이 동작하도록 chat-app 이미지를 CI로 GHCR에 올리고, board의 기존 배포 파이프라인이 그 이미지를 함께 pull·기동하게 한다.

**Architecture:** board `docker-compose.yml`은 이미 `include: [../chat/docker-compose.yml, ../chat/docker-compose.local.yml]` + `env_file: ../chat/.env`로 chat을 끌어온다(board `feature/chat-ui` 브랜치, 2026-09-19). 서버에서도 같은 방식을 유지한다: board `deploy.sh`가 `~/chat`을 clone/reset하고 `~/chat/.env`를 Secrets로 생성한 뒤 `docker compose pull && up`을 하면 chat-app(이미지 `ghcr.io/icesnake72/chat-app:latest`)이 같이 뜬다. chat 저장소의 CI는 테스트 → 이미지 빌드·push만 한다(배포 잡 없음). 트래픽 경로는 `caddy → board-frontend nginx → chat-app:8092`(nginx 규칙은 이미 있음).

**Tech Stack:** GitHub Actions, Buildx + GHA 캐시, GHCR, Docker Compose `include`(v2.20+), Lightsail(Amazon Linux 2023)

**Spec:** `docs/design/2026-09-12-stomp-chat-design.md` 9절(수정 반영), `docs/design/frontend_integration_scope.md` 4절

## Global Constraints

- board 저장소 변경은 **사용자가 board 쪽에서 직접** 한다. 이 문서는 그 변경의 정확한 내용을 적어 둔다(Task B).
- 서버에서 빌드하지 않는다(2GB 무스왑). 이미지는 CI가 만든다.
- 비밀값은 GitHub Secrets → 서버 `.env`. 저장소에 값 없음.
- `JWT_SECRET`은 board와 chat이 **같은 값**이어야 한다. board는 지금 yaml 기본값을 쓰고 있으므로, 이번에 Secret으로 승격해 두 서비스가 같은 Secret을 읽게 한다.

### Task A: chat CI — 테스트 후 이미지 push

**Files:** Create `.github/workflows/build.yml`

```yaml
# chat-app 이미지 빌드·push. 배포는 board 저장소의 deploy.yml이 한다 (이 이미지를 pull).
#   - main push: test → build → ghcr.io/icesnake72/chat-app:latest (+ sha 태그)
#   - PR: test 만
# 인증: 내장 GITHUB_TOKEN (permissions.packages: write). 별도 Secret 불필요.
name: Build chat-app

on:
  push:
    branches: ["main"]
    paths-ignore:
      - "docs/**"
      - "**/*.md"
  pull_request:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  packages: write

concurrency:
  group: build-chat-app-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: "21"
          cache: gradle
      - name: 테스트 (H2 + InMemory denylist, Redis 불필요)
        run: chmod +x ./gradlew && ./gradlew --no-daemon test

  build:
    needs: test
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/icesnake72/chat-app:latest
            ghcr.io/icesnake72/chat-app:${{ github.sha }}
          cache-from: type=gha,scope=chat-app
          cache-to: type=gha,mode=max,scope=chat-app
```

- [ ] 파일 추가 후 main에 push → Actions에서 test·build 통과, GHCR에 `chat-app` 패키지 생성 확인(`https://github.com/icesnake72?tab=packages`)
- [ ] 패키지 가시성: private 유지. board `deploy.sh`는 워크플로 `GITHUB_TOKEN`으로 GHCR 로그인하는데 **그 토큰은 board 저장소 것**이라 chat 패키지를 pull하려면 패키지 설정에서 board 저장소에 read 권한을 주거나(패키지 → Manage Actions access → `icesnake72/boards` read), 패키지를 public으로 둔다. 사용자 결정 사항.
- [ ] 커밋 `ci: chat-app 이미지 빌드·push 워크플로 (test 게이트, GHCR, GHA 캐시)`

### Task B: board 쪽 반영 (사용자가 board 저장소에서)

**B-1. `docker-compose.yml`** — include에서 `local.yml`을 빼고, 운영 Origin과 기동 순서를 추가

```yaml
include:
  - path:
      - ../chat/docker-compose.yml
    env_file: ../chat/.env

services:
  chat-app:
    depends_on:
      redis:
        condition: service_healthy   # denylist 조회가 fail-closed라 Redis 먼저
    environment:
      DB_NAME: chat
      # 브라우저는 80/443 포트를 Origin에서 생략한다. 로컬(caddy http://localhost)과 운영 도메인 둘 다.
      APP_WS_ALLOWED_ORIGINS: https://sbs.alldayai.org,http://localhost,http://localhost:*
```

> include는 `depends_on`으로 board의 `redis`를 참조할 수 있다(병합 후 같은 프로젝트). chat 자체 compose에는 `depends_on`이 없으므로 여기서만 건다.

**B-2. `docker-compose.override.yml`** (신규, `.gitignore`에 추가) — 로컬에서만 8092 개방

```yaml
services:
  chat-app:
    ports:
      - "127.0.0.1:8092:8092"
```

`.gitignore`에 `docker-compose.override.yml` 한 줄. Compose가 자동으로 합치므로 로컬 명령은 그대로 `docker compose up`.

**B-3. `scripts/deploy.sh`** — `.env` 생성 다음, DB 준비 전에 추가

```bash
echo "▶ chat 스택 준비 (compose include 대상)"
[ -d ~/chat/.git ] || git clone https://github.com/icesnake72/chat.git ~/chat
git -C ~/chat fetch --all && git -C ~/chat reset --hard origin/main
cat > ~/chat/.env <<EOF
JWT_SECRET=${JWT_SECRET}
DB_NAME=chat
DB_USERNAME=${DB_USERNAME}
DB_PASSWORD=${DB_PASSWORD}
EOF
```

board `.env` 생성 블록에도 `JWT_SECRET=${JWT_SECRET}` 한 줄을 넣어 board-app이 같은 값을 쓰게 한다(지금은 yaml 기본값). DB 준비 블록의 mysqladmin ping 뒤에:

```bash
docker exec mysql-8 mysql -uroot -p"${DB_PASSWORD}" \
  -e "CREATE DATABASE IF NOT EXISTS chat CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

`docker compose pull`은 include된 chat-app도 함께 받는다. `up -d --no-build --wait --remove-orphans`도 그대로.

> 주의: chat 저장소가 private이면 서버의 `git clone`에 인증이 필요하다. 워크플로 `GITHUB_TOKEN`은 board 저장소 범위라 chat clone엔 못 쓴다. 선택지: (a) chat 저장소를 public으로, (b) 서버에 배포용 read-only PAT 또는 deploy key를 두고 `https://x-access-token:${CHAT_PAT}@github.com/...`로 clone. 이미지 패키지 권한(Task A)과 같은 결정이다.

**B-4. `.github/workflows/deploy.yml`** — Secrets 전달

`env:`에 `JWT_SECRET: ${{ secrets.JWT_SECRET }}` 추가, `envs:` 목록에 `JWT_SECRET` 추가. (b)를 택했다면 `CHAT_PAT`도 같은 방식.

**B-5. GitHub Secrets (board 저장소)**

| Secret | 값 |
|---|---|
| `JWT_SECRET` | board `application.yaml`의 `jwt.secret` 기본값과 같은 값(현재 운영이 그 값으로 토큰을 발급 중이므로 바꾸면 기존 refresh 세션이 무효화된다. 유지하려면 같은 값, 교체하려면 배포 직후 사용자 재로그인 안내) |
| `CHAT_PAT` (선택) | chat 저장소 read 권한 PAT |

**B-6. nginx** — 변경 없음. `frontend/nginx.conf`의 `/api/v1/chat/`·`/ws`(Upgrade 헤더) 규칙이 로컬과 운영 공용이다. `proxy_read_timeout`이 WebSocket 유휴 시간보다 길어야 하며(heartbeat 10s라 기본 60s도 안전), 규칙에 `3600s`가 있으면 그대로 둔다.

## 위험과 대비

| 위험 | 대비 |
|---|---|
| 서버 compose가 include 미지원 | Task C 첫 항목에서 확인. 미지원이면 board compose에 chat 서비스 블록 복사(이미지·env·healthcheck) — `frontend_integration_scope.md`에 블록 예시 |
| chat 저장소·패키지 private 권한 | Task A/B-3의 선택지 중 하나를 배포 전에 정한다. 가장 단순한 것은 둘 다 public |
| `JWT_SECRET` 불일치 | 배포 직후 `curl https://sbs.alldayai.org/api/v1/chat/me -H "Authorization: Bearer <board 로그인 토큰>"`이 200이어야 한다. 401 `LOGIN_REQUIRED`면 값 불일치 |
| Redis fail-closed | chat-app이 `board-redis`에 못 붙으면 모든 인증이 500. `depends_on: redis healthy`로 기동 순서만 보장 |
| board `.env`가 chat 변수 오염 | board compose가 `DB_NAME: chat`을 리터럴로 고정했다(이미 반영). `~/chat/.env`는 별도 파일 |
